# API endpoints used by the frontend

The frontend never calculates anything from data itself, it only calls these endpoints.
Endpoints the backend doesn't have yet are served by a mock server so the UI works today.

## Running locally

```bash
# 1. Backend (port 8000) and frontend (port 5173), from the project root
docker compose up -d

# 2. Mock API for the missing endpoints (port 8001), also from the project root
python3 frontend/mock_api/mock_server.py
```

The mock server only uses the Python standard library and reads `data/f1-fantasy-data` for prices.

`src/api/endpoints.ts` decides where each call goes. When the backend implements an endpoint,
change its line from `MOCK_API` to `REAL_API`.

Mock data lives in `frontend/mock_api/` and is regenerated with the scripts there:

| File | Generated by |
|---|---|
| `mock_predictions.json` | `predictionMocker.py` |
| `mock_constructors.json` | `predictionconstmocker.py` |
| `mock_stats.json` | `statsMocker.py` (reads `data/kaggle-base-data`) |

## Overview

| Method | Path | Status | Used for |
|---|---|---|---|
| GET | `/drivers/` | Backend | Driver roster, prices, colours |
| GET | `/constructors/` | Backend | Constructor roster, prices, colours |
| GET | `/races/upcoming` | Mock | Race dropdown |
| GET | `/predictions` | Mock | Points on every card, PPM graph, picker |
| GET | `/stats/drivers` | Mock | Comparison panel and card info popup (hexagon, season stats, last 5) |
| GET | `/stats/constructors` | Mock | Comparison panel for teams |
| POST | `/teams/evaluate` | Mock | Team info totals, DRS Boost, points share, distribution graph |
| POST | `/optimize` | Mock | Optimize button |

All ids are the fantasy `player_id`, the same ids `/drivers/` and `/constructors/` return.

Shared settings sent with predictions, evaluate and optimize:

| Name | Type | Meaning |
|---|---|---|
| `rounds` | list of round numbers | Races to sum points over (one round now, up to three later) |
| `risk` | `floor` \| `expected` \| `ceiling` | Which prediction PPM, shares and the optimizer use (P10 / P50 / P90) |
| `form` | 0–100 | How much recent form boosts or lowers points |
| `track` | 0–100 | How much track-type fit boosts or lowers points |
| `dnf` | 0–100 | How much the DNF chance reduces points |

## Missing endpoints

### GET `/races/upcoming`

Races that haven't happened yet, ordered by round.

```json
[
  {
    "round": "20",
    "name": "Sao Paulo Grand Prix",
    "date": "2026-11-08",
    "circuit": "Autódromo José Carlos Pace",
    "location": "São Paulo",
    "trackType": "high_speed"
  }
]
```

`trackType` is `street`, `high_speed` or `technical`.

### GET `/predictions?rounds=20&risk=expected&form=50&track=0&dnf=0`

One entry per selectable player with the settings already applied. Points are summed over `rounds`.

```json
[
  {
    "id": "131",
    "kind": "driver",
    "floor": 12.4,
    "expected": 24.0,
    "ceiling": 38.1,
    "ppm": 0.85,
    "multiplier": 1.08,
    "dnfChance": 6.5,
    "qualiPos": 4,
    "racePos": 3
  }
]
```

- `ppm` = points for the chosen `risk` per €1M.
- `multiplier` = combined effect of the settings (1.08 = +8%).
- `qualiPos` / `racePos` are only for drivers.

### GET `/stats/drivers?round=20` and GET `/stats/constructors?round=20`

Non-fantasy stats. `trackFit` and `trackAvg` depend on the circuit of `round`.

```json
[
  {
    "id": "131",
    "code": "VER",
    "ratings": { "quali": 81, "race": 71, "form": 96, "reliability": 22, "overtaking": 71, "trackFit": 52 },
    "season": {
      "starts": 17, "wins": 2, "podiums": 9, "points": 221.0,
      "avgQuali": 5.0, "avgFinish": 7.2, "bestFinish": 1, "dnfs": 4,
      "avgGained": 2.1, "avgPitStop": 23.67
    },
    "trackAvg": 4.5,
    "recentFinishes": [
      { "race": "Singapore", "position": 1, "dnf": false }
    ]
  }
]
```

- All `ratings` are 0–100 compared with the 22-car grid.
- `form` = average finish over the last 5 races (last 10 results for constructors).
- `trackFit` = how much better than their own average they finish on this track type (50 = no difference).
- `trackAvg` = average finish at this circuit since 2023 (`null` if never raced there).
- `avgPitStop` = average pit lane time in seconds.
- `recentFinishes` = the last 5 races, oldest first. For constructors `position` is the best car and `dnf` is true only if no car finished.

### POST `/teams/evaluate`

Totals for a team.

Request:

```json
{
  "drivers": ["131", "12", "118", "114", "125"],
  "constructors": ["2641", "26"],
  "drs": "118",
  "rounds": ["20"],
  "risk": "expected",
  "form": 0,
  "track": 0,
  "dnf": 0
}
```

Response:

```json
{
  "cost": 58.8,
  "floor": 106.2,
  "expected": 181.5,
  "ceiling": 289.6,
  "drs": "118",
  "players": [
    { "id": "118", "points": 54.2, "share": 25, "drs": true }
  ]
}
```

- `drs` = the DRS Boost driver (or `null`). Their points count double in all totals and in `players`. Ignored if the driver isn't in the team.
- `players` is sorted by points for the chosen `risk`; `share` is the % of the team's points.

### POST `/optimize`

Best 5 drivers + 2 constructors within budget, maximising the points for `risk` with the DRS Boost (2x) on the best driver.

Request: same settings as evaluate plus `"budget": 100`.

Response:

```json
{ "drivers": ["129", "111", "118", "124", "114"], "constructors": ["2636", "210"], "drs": "118", "points": 219.8 }
```

Returns status `422` with `{ "error": "No team fits the budget" }` if nothing fits.
